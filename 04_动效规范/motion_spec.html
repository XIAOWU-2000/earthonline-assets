一、设计原则

1.1 三条铁律

# 原则 说明
1 每一步都给反馈 用户做了任何动作，200ms 内必须有视觉变化，禁止静默
2 反馈必带世界观 转场 / 加载 / 出牌都该有"卦象」「代码雨」「符文」等元素，不是通用 loading
3 动效服从功能 动效要解释"为什么这个动作发生了"，不为了炫技

1.2 反内卷动效原则

  • 不动不必要的东西：动效是为信息服务的，纯装饰 = 噪音
  • 短比长好：用户等 1.2s 看到结果，远比等 3s 看到华丽过程舒服
  • 可关闭：所有"长动效"必须能跳过（点击/滑动手势）

二、时长令牌

Token 时长 用途
dur.snap 80ms 按下/松开瞬间反馈
dur.fast 200ms 按钮、切换、hover
dur.base 320ms 展开、淡入、状态切换
dur.slow 560ms 转场、扇形展开、卦象旋转

单次交互不要超过 slow。用户等动效的时间不超过 1 秒。

2.1 缓动函数

Token 曲线 用途
ease.standard cubic-bezier(0.2, 0, 0, 1) 默认
ease.decelerate cubic-bezier(0, 0, 0.2, 1) 入场（结束减速）
ease.accelerate cubic-bezier(0.4, 0, 1, 1) 离场（开始加速）
ease.glitch 自定义：3 个随机错位关键帧 故障效果（见 §5.3）

三、关键交互时间轴（具体到毫秒）

3.1 启动序列

0ms    ──►  代码雨充满屏幕（fade in，560ms）
200ms  ──►  Logo 浮现（scale 0.9→1.0，320ms，ease.decelerate）
600ms  ──►  Logo 闪烁 1 次（glitch 80ms）
720ms  ──►  Logo 稳定
800ms  ──►  代码雨渐隐（320ms，ease.accelerate）
1120ms ──►  跳转今日页

启动总时长 1.12s，用户的等待感是"有内容在动"而不是"白屏转圈"。

3.2 今日页入场

0ms    ──►  顶部状态条 fade in（200ms）
120ms  ──►  今日状态数字滚动（count-up，320ms）
320ms  ──►  今日之劫卡片从下方滑入（translateY 80→0，320ms，ease.decelerate）
        ──►  卡片背景代码雨微动（opacity 0.08 → 0.12 → 0.08，循环 4s）
560ms  ──►  算力条从 0 增长到当前值（640ms，ease.decelerate）
        ──►  + 按钮 fade in + scale 0→1（200ms）

3.3 事件提交 → 起课

这是全产品最关键的转场，动感最强。

用户点击提交按钮
  │
  ├─ 0ms     ──►  按钮按下（scale 1.0→0.94，80ms，ease.accelerate）
  ├─ 80ms    ──►  按钮回弹（scale 0.94→1.0，200ms，ease.standard）
  │
  ├─ 100ms   ──►  屏幕中央出现"卦眼"（圆形径向收缩，320ms）
  │                  背景：卦象符号 ☰☱☲☳ 快速翻转（40ms/帧）
  │                  边框：单层 1pt 霓虹青
  │                  内部：可滚动文本"起课中..."
  │
  ├─ 320ms   ──►  卦眼扩张 + 卦象定格
  │
  ├─ 480ms   ──►  故障效果（glitch 120ms，画面 RGB 错位 ±3pt）
  │
  ├─ 600ms   ──►  画面清空，露出解法页
  │
  └─ 800ms   ──►  解法页"层·表层"卡片滑入（320ms，ease.decelerate）

关键：卦象翻滚 → 定格 → 故障 → 解法——这一秒多让人感觉"系统在算命"而不是"系统在加载"。

3.4 解法生成（三层依次展开）

0ms    ──►  卦象缩回圆点（200ms）
200ms  ──►  卦点分裂为三颗，沿三条不同轨迹飞向屏幕的三个区域
         ──►  表层卡：从顶部下落
         ──►  中层卡：从右侧滑入
         ──►  深层卡：从底部上浮
560ms  ──►  三张卡到位（错落 80ms）
640ms  ──►  话术三档按钮 stagger 进入（每档 60ms）

3.5 出牌（应劫）

动感最强的一步，也是产品的核心动作。

0ms    ──►  选中牌从手牌中跳出（scale 1.0→1.08，translateY 0→-12，120ms）
120ms  ──►  牌飞向屏幕中央（200ms，ease.standard）
320ms  ──►  牌在中央**旋转 360°**（200ms，ease.decelerate）
520ms  ──►  牌爆开为卦象碎片 + 故障效果（glitch 150ms）
670ms  ──►  碎片聚成一句行动指令（"整理三项产出 10 分钟"）
820ms  ──►  行动指令飞向顶部"执行中"区域（200ms）
1020ms ──►  顶部出现"开始计时"提示 + 锁屏提醒授权请求

总时长 1.02s，但每一步都有反馈，用户不会觉得"卡"。

3.6 结算

0ms    ──►  用户点击"完成"按钮（按压反馈 80ms）
80ms   ──►  弹出结算面板（从下往上滑入 320ms，ease.decelerate）
        ──►  面板背景：径向暗化（rgba 0,0,0,0.6）淡入
200ms  ──►  三个选项（全部完成 / 一部分 / 没开始）逐个出现（stagger 80ms）
        ──►  每个选项点击时（scale 0.96→1.0，120ms）
        ──►  选中后选项边框发青色辉光（box-shadow 0 0 16px #00F0FF，240ms）
选中 ──►  进度条从旧值滑到新值（640ms，ease.decelerate）
        ──►  顶部出现"已结算"提示（fade in 200ms，2s 后 fade out）

四、视觉动效

4.1 代码雨（卦象版）

项 规格
字符 ☰☱☲☳☴☵☶☷ + 干支字
列宽 26pt
下落速度 2–4 列/秒，逐列随机
头尾渐变 头部 100% 透明 → 尾部 0% 透明（线性）
头部字符 矩阵绿 #00FF41 + 8pt 辉光
出现位置 仅：启动页、加载态、空状态、结算面板背景
出现位置 禁：正文阅读区、列表项、卡片正文

4.2 辉光

应用 规格
按钮激活 box-shadow: 0 0 16px #00F0FF，240ms
卡牌稀有（史诗/传说） 双层 box-shadow: 0 0 12px #00F0FF, inset 0 0 8px #00F0FF40
选中态 单层青色辉光，320ms 渐入
错误态 单层品红辉光 #FF003C，禁用 pulse（不让人焦虑）

辉光必须用 box-shadow 双层（禁用 filter: blur() 与 BackdropFilter，性能灾难）。

4.3 故障（glitch）

@keyframes glitch {
  0%   { transform: translate(0, 0); filter: none; }
  20%  { transform: translate(-3px, 1px); filter: hue-rotate(15deg); }
  40%  { transform: translate(2px, -2px); filter: hue-rotate(-10deg) saturate(1.3); }
  60%  { transform: translate(-1px, 0); filter: none; }
  80%  { transform: translate(2px, 1px); filter: hue-rotate(20deg); }
  100% { transform: translate(0, 0); filter: none; }
}
项 规格
时长 80–150ms（绝不超出 200ms，否则显廉价）
同元素 2s 内最多 1 次
触发场景 起课、出牌、错误提示

4.4 扫描线

项 规格
样式 水平 1pt 线，间隔 3pt
透明度 3%–5%（超过 8% 显著影响可读性）
出现位置 终端/日志类区域
可关闭 设置里有开关（防闪烁敏感用户）

4.5 卦象旋转（出牌特效）

选中牌 → 旋转 360°（200ms，ease.decelerate）
  → 爆开为卦象碎片
  → 碎片聚成行动指令

旋转必须带缓动（linear 太机械，ease.decelerate 自然）。

五、性能与降级

5.1 三级视觉质量

enum VisualQuality { high, medium, low }
级别 配置
high 代码雨 + 辉光 + 故障 + 扫描线
medium 代码雨（列数减半）+ 辉光，无扫描线无故障
low 全静态，无动画无辉光

5.2 降级触发

  • 启动时跑 3s 帧率采样，< 50fps 自动降一级
  • 设置里可手动切（用户偏好）
  • 低端机必须能跑 low（功能完整）

5.3 性能底线

指标 目标
冷启动 ≤ 1.5s
起盘 ≤ 50ms
起课 ≤ 80ms
列表滚动 稳定 60fps（high）/ 40fps（medium）
出牌全过程 ≤ 1.2s（用户等动效的时间不超过 1.5s）

5.4 禁用清单（性能灾难）

  • ❌ BackdropFilter
  • ❌ ImageFilter.blur
  • ❌ AnimatedOpacity 嵌套超过 3 层
  • ❌ Transform.scale 超过 1.5（会模糊）
  • ❌ 同时运行的 CustomPaint 超过 5 个

六、世界观一致性

元素 动效用法
卦象 入场翻转、选中旋转、出牌爆开
代码雨 启动、空状态、加载
故障 起课、出牌、错误
辉光（青色） 选中、激活、可点击
辉光（品红） 劫怪登场、警示
扫描线 终端/日志区域
符文闪烁 解法出现（稀有用）

每种动效只能对应一种世界观含义，不能乱用。

八、特殊场景

8.1 空状态

项 规格
动效 极简 —— fade in 320ms 即可，禁用任何跳动/缩放
元素 静置卦象符号（☵），无循环动画（不要吸引注意力）
文案 中性，不制造焦虑（详见方案 10.5）

8.2 错误反馈

项 规格
动效 shake 3 次（左右 4pt），200ms
颜色 边框短暂变红 1s，不持续
文案 短句 + 操作建议
声音 不触发（用户已经出错了，再来声音是骚扰）

8.3 长时间操作（>1s）

阶段 反馈
0–500ms 进度条或 spinner
500ms+ 出现具体进度文案（"已起课 8%"）
1s+ 出现"跳过"按钮（用户可主动取消）
2s+ 必须有"遇到问题？"反馈入口

九、A/B 测试点位（可选）

测试项 变量 衡量
出牌动效时长 0.8s / 1.0s / 1.2s 完成率
解法生成是否带卦象动画 有 / 无 用户对"个性化"的感知
故障触发频率 1s / 2s / 4s 是否引发焦虑

不强求 A/B，先看留存数据再决定。
